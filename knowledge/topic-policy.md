# 主題庫管理與審核

## 範圍與來源

MVP 採用專案維護者整理的固定主題庫，不接受玩家即時新增主題。真人版的 12 個主題保存在 Neon 遷移的 `join_matchmaking` 與 `start_next_round` 中；展示版的對應主題與示範謎題保存在 `site/app.js`，既有 Supabase 原型亦保留同一清單。主題只是出題方向，玩家自行撰寫的謎題、暱稱及聊天室內容不在本流程的事前審核範圍。

## 新增或修改流程

1. 以 Git 變更提出主題、用途和示範題；主題要簡短、容易理解，並能想出不只一個合適的謎題。
2. 檢查是否含有仇恨、騷擾、露骨性內容、暴力細節，或鼓勵揭露姓名、聯絡方式、精確位置及其他個人資訊；也要避免以身分、文化或身心狀況作為笑點。無法通過時先修改或不收錄。
3. 至少由一名沒有撰寫該變更的維護者檢查內容、可理解性及兩種模式的一致性；目前沒有第二位維護者時，該項保持待審，不直接發布。
4. 更新 Neon 真人模式的兩份主題陣列、既有 Supabase 原型、展示版主題及示範謎題，檢查主題數量、順序、題目合理性、提示不直接透露答案，以及介面上顯示的總數。執行 `node --test tests/topics.test.mjs`。
5. 在測試環境套用資料庫變更並完成雙訪客檢查後才發布。已套用的資料庫遷移不應直接改寫：新增向前遷移更新 RPC，並在回退時以另一個遷移恢復舊內容。前端和資料庫的上線順序與相容性要在變更說明中記錄。

## 回報與下架

發現不適當或容易誤解的主題時，維護者應記錄主題及問題、暫停使用並安排修正；緊急下架時優先讓真人與展示版一致，完成後補上審查及測試記錄。玩家產生內容的檢舉、封鎖及處理流程另列於路線圖，不能由主題事前審核取代。
